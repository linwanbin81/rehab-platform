# 训练计划与摄像头跟练衔接实施计划

**目标** 让指导者保存基线和发布计划，训练者从计划直接完成一组摄像头练习，再由指导者查看和复核结果。

**设计** `docs/superpowers/specs/2026-11-20-rehab-platform-next-design.md`。本阶段继续复用已验证的摄像头和模型模块，以逐组保存的方式接入关系数据。同一计划可配置多个动作和组。整会话多组编排、跨刷新恢复和证据时间轴是后续独立任务。

- [x] 以 HTTP 测试验证角色和数据归属。新增账号、指导关系、基线版本与计划明细表，演示库预置互相隔离的指导关系。
- [x] 用独立测试验证计划录入和发布。指导者可为自己负责的训练者配置日期、动作、训练侧、组次与目标；训练者读取自己的已发布计划。
- [x] 从工作台选计划、动作和组进入真实摄像头界面，锁定计划参数。原摄像头入口继续支持试练。服务端校验计划归属并用数据库中的目标配置复算，报告保留计划明细、组号和训练者。
- [x] 通过训练者和指导者端打开计划报告。验证越权失败、报告重试防重、逐项复核与单独提交最终结论。
- [x] 跑前端构建、后端集成和浏览器摄像头回归，在 `8081` 验证训练者从计划开练并保存，指导者能读取同一记录。

## 复核修正与实施决定

- 启动脚本检查源码时间，避免继续运行旧 JAR；提供显式强制重建入口，仅停止该项目拥有的后端监听进程。
- 训练中 401 不清除内存帧，允许原训练者重新登录并重试相同采集请求。浏览器回归进一步复现下一组仍带旧令牌而返回 401，修正为将新令牌同步到当前计划任务后通过。
- 分项复核发生未保存编辑时禁用最终提交，比较草稿决定及备注与已保存状态；单元及页面回归通过。
- 已卸载工作台的登录/退出响应不能修改当前标签页的新登录；延迟退出浏览器回归通过。
- 本阶段采用逐组报告及 Spring JDBC/H2 执行已批准流程，便于先验证真实操作；尚无整体会话完成率、MySQL/MyBatis 接入或计划版本调整。后续迁移需增加会话与组实体并重新验收数据库兼容性。
