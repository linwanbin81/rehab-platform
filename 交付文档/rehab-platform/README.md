# 舒展 康复训练辅助平台 第一版

本版用于运行和确认项目流程。实现 Vue 3 页面、Java Spring Boot 与 MyBatis 业务后端、Python 规则分析服务和真实关系数据库读写。所有动作数据都明确标为模拟数据；不包含真实摄像头姿态识别、训练好的 PyTorch 模型和医疗评价。

## 在这台电脑上直接运行

目前已经完成构建，Java 和 Python 服务默认使用 8080、8001 端口。

1. 打开 `http://127.0.0.1:8080`。
2. 如果服务未启动，双击项目目录的 **启动平台.cmd**；它调用 `start.ps1 -SkipBuild`，不需要重新下载依赖。
3. 停止服务可双击 **停止平台.cmd**。

| 身份 | 账号 | 密码 | 可体验的功能 |
| --- | --- | --- | --- |
| 训练者 | `trainee` | `Demo123!` | 查看计划、模拟跟练、报告回放、花朵互动 |
| 指导者 | `teacher` | `Demo123!` | 发布计划、查看负责用户的报告、确认或驳回事件、添加反馈、发布下一版本 |
| 管理员 | `admin` | `Demo123!` | 查看全部演示业务记录、数据表计数和查询执行计划 |

另有 `teacher2` 与 `trainee2`，密码相同，用于演示独立指导关系与越权拒绝。均为初始化演示账号。

## 推荐体验路径

1. 使用训练者账号，进入“我的训练计划”，选择“肩肘基础训练”。
2. 点击“开始模拟训练”，观察骨架、计数、角度曲线和预设偏差提示。
3. 点击“查看完整报告”；点击某条幅度、节奏或躯干问题，定位对应时间的骨架与曲线。
4. 左下角退出，切换指导者；进入报告，对具体问题确认或驳回，或添加总体反馈。
5. 点击“调整后续计划”，修改次数、目标区间和安排日期，发布新版本。旧计划与旧报告仍可查询。
6. 切回训练者体验花朵互动。按住鼠标或空格键闭合，松开绽放；可关联会话并保存次数、时长。
7. 使用管理员进入“数据库概览”，刷新各表记录数，观察训练、反馈和游戏记录如何入库。

本工作区完成联调后已保留少量演示计划和报告。下载源码包到新目录时，首次启动只初始化账号、动作和基础计划，完成模拟跟练即可生成报告。

## 技术结构

```text
Vue 3 + Element Plus + ECharts
           │ REST API
Spring Boot + MyBatis ─── MySQL / 默认 H2
           │ HTTP / JSON
Python 标准库规则服务（8001）
```

- `web/`：训练者、指导者、管理员页面。开发时使用 Vite 代理，发布时由 Java 直接提供构建好的静态页面。
- `server/`：Spring Boot 2.7.18，兼容本机现有 Java 8。`Store.java` 集中展示 MyBatis SQL；`RehabService.java` 组织归属检查、事务、结果入库和复核。
- `algorithm/`：Python 3 标准库服务，不需要 pip 安装。确定性生成动作特征，按实际参数计算幅度、节奏、躯干、保持等分项结果，不生成随机质量分数。
- `database/`：MySQL 8 建表脚本、典型联表统计 SQL 和数据关系说明。
- `tests/`：跨服务联调脚本。
- `.runtime/`：启动后产生的 PID 和日志。

首版使用轻量业务实现，没有直接复制若依或康复演示项目的源码。后续升级 Java 17 / Spring Boot 3 和真实姿态识别时，可以保留数据库关系和 API 思路。

## 数据库与持久化

默认使用 H2 文件数据库，文件为 `server/data/rehab.mv.db`。关闭和重新打开平台不会丢失训练记录。数据库只由 Java 业务服务写入，Python 不直接操作业务表。

连接参数见 `server/src/main/resources/application.yml`。使用外部数据库工具查看 H2 文件时，应先停止 Java 服务，避免文件锁冲突。H2 JDBC URL 使用文件绝对路径，并附上 `MODE=MySQL;DATABASE_TO_LOWER=TRUE`；账号 `sa`，演示密码 `local-demo-db`。

16 张表包括用户、登录会话、指导关系、训练基线、动作模板、规则版本、计划、计划明细、训练会话、组记录、单次动作、问题事件、特征采样、指导复核、计划调整和游戏记录。

已经实现：

- BCrypt 密码摘要；登录 token 只在数据库保存 SHA-256 摘要，8 小时过期，注销立即撤销。
- 后端按本人或指导关系限制计划、会话、事件与报告访问。
- 训练结果的多表写入使用同一个事务；Python 调用在事务之外完成。
- 会话行锁和状态检查保证重复、并发完成请求不会重复插入动作记录。
- 外键、同组动作序号唯一约束、特征时间唯一约束与参数范围约束。
- 会话保存当时计划和规则快照；后续调整创建新计划行并保存调整记录。
- 人工复核是新增留痕记录，系统原始事件不被覆盖。
- 训练历史与事件定位的复合索引，管理员可查看 EXPLAIN 结果。

### 切换 MySQL 8

本机未检测到 MySQL，当前已验证 H2；MySQL 配置和脚本已提供，尚未在真实 MySQL 服务上联调。

1. 安装并启动 MySQL 8，通过 Workbench 或其他 SQL 工具执行 `database/01_schema_mysql.sql`。初始化不删除现有数据。
2. 停止当前平台。
3. 在 PowerShell 中设置数据库账号后启动：

```powershell
$env:DB_USER = '你的数据库账号'
$env:DB_PASSWORD = '你的数据库密码'
.\start.ps1 -SkipBuild -MySql
```

默认连接 `127.0.0.1:3306/rehab_platform`；可用 `DB_URL` 覆盖完整 JDBC 地址。Java 在空用户表中初始化演示数据。H2 和 MySQL 是两个独立数据库，切换不会自动迁移已有训练记录。

## 修改代码后重新构建

需要 Java 8 或更高版本、Node.js 20+ 和 Python 3.10+。已构建版本直接运行只需要 Java 与 Python。

```powershell
.\stop.ps1
.\start.ps1
```

首次构建会下载 Maven 3.9.9（校验 SHA-512）和前后端依赖，需要网络。Maven 与缓存保存在工作区 `.tools`，不修改系统 Maven 安装。

前端热更新开发可单独运行：

```powershell
cd web
npm ci
npm run dev
```

访问 `http://127.0.0.1:5173`，业务 API 代理到 8080。

单独启动后端与算法服务：

```powershell
# 终端一
python algorithm/service.py
# 终端二，工作目录须为 server，以保持 H2 数据文件位置一致
cd server
java -Dfile.encoding=UTF-8 -jar target/rehab-platform-0.1.0.jar
```

## 测试

```powershell
cd algorithm
python -m unittest -v test_service.py
cd ..
python tests/smoke_test.py
python tests/transaction_check.py
```

联调脚本会新增清楚命名的演示计划、报告和反馈；重复运行会增加新的演示记录。检查认证、指导关系、参数校验、并发防重、分项标签、复核、CSV 导出、计划版本、游戏关联、数据库概览和注销失效。

`transaction_check.py` 使用独立内存数据库和测试端口 18082 / 18001，故意制造特征时间重复，验证已写入的组、动作、事件和特征全部回滚；随后验证可正常重试及并发调整只产生一个后续版本，不修改演示数据库。

## 日志与常见问题

- 打不开页面：运行 `启动平台.cmd`，查看 `.runtime/java.out.log` 和 `java.err.log`。
- 提示 Python 未就绪：查看 `.runtime/python.err.log`，确认 8001 未被其他程序占用。
- 8080 被占用：关闭占用程序或修改端口及对应脚本地址；脚本不自动终止其他项目进程。
- 提示 jar 或前端构建缺失：运行 `构建并启动.cmd`。
- 修改源码后页面不变：停止服务，重新构建并启动，再刷新浏览器。
- 数据文件应备份时：先停止 Java，复制 `server/data/rehab.mv.db`；不要在运行过程中覆盖数据库文件。
